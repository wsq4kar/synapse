# Что сделано в этом чате

Итог работы над Synapse от версии 0.2.0 до 0.4.1 и исправлений установщика.

## Релизы

| Версия | Что в ней | Статус |
|---|---|---|
| 0.4.0 | Antigravity CLI, OpenRouter, models.json, экономия токенов, статистика, меню аккаунта, смена имени | опубликована, workflow собрал установщик |
| 0.4.1 | Обход Antigravity через AGUnlocker | опубликована, **последняя** |
| после 0.4.1 | Установщик ждёт закрытия Synapse перед копированием файлов | в `main`, в релиз не вошла |

Ветка `main` обновлена через pull request [#1](https://github.com/wsq4kar/synapse/pull/1) (0.4.0 и 0.4.1) и [#2](https://github.com/wsq4kar/synapse/pull/2) (установщик).

## Агенты для кода

- **Antigravity CLI (`agy`) вместо Gemini CLI.** Приложение запускает `agy` в режиме stream-json: читает шаги, рассуждения, субагентов, токены, продолжает сессию по `--conversation`. Список моделей берётся из `agy models`. Старые настройки `gemini-cli` переносятся автоматически (`migrateGeminiCli` в `store.js`).
- **Обход регионального блока (AGUnlocker).** Причина ошибки 400 «User location is not supported»: обход патчит `agy` и читает прокси из `AG_LS_PROXY`, а Synapse передавал ему ещё и свой `HTTPS_PROXY`, поэтому запросы шли мимо обхода. Теперь при установленном обходе `agy` получает только `AG_LS_PROXY`. Переменная читается из реестра Windows или из `~/.config/environment.d` на Linux, поэтому работает даже если Synapse был запущен до установки обхода. В ходе задачи появляется шаг «Обход Antigravity». Остальные агенты продолжают использовать прокси Synapse.
- **Сессии для Codex и Antigravity.** Раньше продолжали сессию только Claude и OpenCode. Теперь все четыре агента (Claude, Codex, Antigravity, OpenCode) продолжают свой диалог, а история чата не пересылается заново. Если сессию продолжить не удалось, задача перезапускается один раз с кратким контекстом.

## OpenRouter

- Новый модуль `src/main/executors/openrouter.js`: чат со стримингом и рассуждениями, маршрутизация задач, генерация изображений, список моделей, проверка ключа.
- Кэширование промпта для моделей Anthropic и Google через OpenRouter.
- Ключ хранится зашифрованным вместе с ключом Gemini. Если ключа Gemini нет, чат, маршрутизатор и изображения работают через OpenRouter.
- Агент OpenCode получает ключ для моделей `openrouter/…`, остальные агенты ключ не видят.
- Во вкладке настроек «Ключи API» появились поля для Gemini и OpenRouter с выбором моделей.

## Модели без ручного ввода

- Все списки моделей (агенты, OpenRouter, Арена) лежат в `src/main/models.json`.
- `src/main/catalog.js` читает этот файл и раз в 6 часов скачивает свежую версию с GitHub.
- Личные дополнения можно положить в `data/models.json` в папке данных приложения.
- Поле «Ещё» в настройках агентов стало необязательным.

## Экономия токенов

- **История для агентов без сессии** (`src/main/tokens.js`): блоки кода из прошлых ответов сворачиваются, длинные сообщения сокращаются.
- **История для чатов Gemini и OpenRouter**: последние 4 сообщения идут целиком, остальные сокращаются, общий объём ограничен 48 000 символами.
- **Выбор исполнителя**: в запрос уходит только начало текста, рассуждения модели-маршрутизатора отключены.
- **Арена**: участникам с сессией не пересылаются бриф и их собственный план.

## Статистика и интерфейс

- **Страница «Статистика»** (отдельный пункт в боковой панели и в меню аккаунта): токены за всё время, максимум за день, самая длинная задача, серии дней, карта активности (по дням, по неделям, нарастающим итогом), расход по исполнителям, любимые модели, частый уровень рассуждений, использование Ultra и Арены.
- **Учёт токенов**: журнал `usage.jsonl` хранит компактную запись по каждой задаче. Задачи, сделанные до появления статистики, подтягиваются из сохранённых чатов.
- **Меню аккаунта** в духе Claude: настройки, статистика, язык, агенты и модели, ключи API, «Что нового» (показывает `CHANGELOG.md`), справка.
- **Поиск в настройках** по названиям разделов и ключевым словам.
- **Смена имени**: кнопка «Изменить» на странице статистики, пункт меню «Изменить имя» и поле в «Настройки → Внешний вид». Пустое поле возвращает имя пользователя Windows.

## Исправления

- В `gemini.js` локальная переменная `t` закрывала функцию перевода, из-за этого сообщения «Остановлено» и «заблокировано фильтром» не выводились.
- В `arena.js` и `router.js` тоже убраны конфликты имён.
- При переходе на новую страницу прокрутка больше не переносится с предыдущей.
- Убран пункт «Gemini CLI» из проверки брандмауэра (агент больше не поддерживается).

## Сборка и релизы

- **Ручной запуск релиза.** Эта среда не даёт пушить теги, поэтому в `.github/workflows/release.yml` добавлен запуск вручную с полем «тег». Workflow создаёт тег и релиз на выбранном коммите и подставляет описание из `CHANGELOG.md`.
- **Установщик.** Сначала workflow запускал `electron-builder` напрямую, и он ломался: PowerShell неправильно разбирал флаг `-c.win…`, а сам electron-builder пытался использовать `build/installer.nsi` как свой скрипт и падал на дублирующем `VERSION`. Теперь приложение собирается через `electron-builder --dir`, exe получает иконку и версию через `build/set-exe-icon.mjs`, а установщик собирается штатным `makensis` из `build/installer.nsi`.
- **Ошибка «Невозможно открыть файл для записи» при установке поверх запущенного Synapse.** Установщик теперь ждёт до 15 секунд, пока `Synapse.exe` освободится, и только потом копирует файлы. Скрипт проверен компиляцией в NSIS 3.09. На Windows не проверялся. Попадёт в следующую версию.
